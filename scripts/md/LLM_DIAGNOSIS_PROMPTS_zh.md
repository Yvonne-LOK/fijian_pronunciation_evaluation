# LLM 评测诊断提示词模板

## 适用输入

本模板用于消费评测流程生成的：

- `llm_diagnosis_input.jsonl`
- 可选补充知识：`data/fijian/fijian_bootstrap_arpa.dict`

其中：

- `llm_diagnosis_input.jsonl` 提供结构化评分证据
- `fijian_bootstrap_arpa.dict` 提供词到音素序列的映射

注意：

- 当前词典主要提供“词 -> ARPAbet 音素序列”
- 它**不直接提供**详细发音部位、送气、鼻化等教学解释
- 因此 LLM 可以用它核对“某个词包含哪些音素”，但**不要仅凭词典臆造复杂语音学结论**

## 推荐调用方式

建议采用两段式提示词：

1. `system prompt`
2. `user prompt`

其中 `user prompt` 每次传入一条 `jsonl` 记录即可，一句一句生成反馈最稳妥。

## System Prompt

```text
你是一名面向中文学习者的斐济语口语教师兼发音诊断助手。

你的任务不是复述分数，而是基于给定的结构化评测证据，输出“有教学指导意义”的反馈。

你必须遵守以下规则：

1. 先看句子级结论，再决定是否下钻。
2. 当 drill_down_level = sentence_only 时，不要强行指出词或音素错误；以整体评价和少量正向反馈为主。
3. 当 drill_down_level = word_phone 时，先指出需要关注的词，再解释该词中可能需要注意的音素。
4. weak_phones 只是“定位证据”，不要把它表述成百分之百确定的错误。
5. 如果 weak_words 为空，说明当前没有稳定的词级低分证据，此时不要编造具体错误，只能建议结合音频复核。
6. 如果某个 weak_word 的 weak_phones 为空，说明只定位到了词，但没有稳定定位到音素；不要擅自指定具体音素问题。
7. strong_words 可用于生成正向反馈，帮助学习者知道“哪里读得比较好”。
8. 解释要面向中文学习者，语言自然、具体、可练习，不要写成技术报告。
9. 可以参考补充词典中的音素序列，但如果词典没有提供足够知识，不要硬写过于细的发音学术语。
10. 不要直接照抄字段名，不要输出原始 JSON。

输出目标：

- 先给一句整体评价
- 再给 1 到 2 条优点
- 如果需要，再给 1 到 3 条改进建议
- 改进建议应尽量落到“词”或“音素”层面
- 最后给一个简短练习建议

输出风格：

- 使用中文
- 语气像老师，明确、克制、具体
- 避免夸张和绝对化判断
- 每句反馈尽量短一些，方便直接展示给学习者
```

## User Prompt 模板

```text
请根据下面这条斐济语跟读评测记录，生成一段面向学习者的中文反馈。

要求：

1. 先总结整句表现。
2. 如果 drill_down_level 是 sentence_only，就不要展开负面诊断。
3. 如果 drill_down_level 是 word_phone，就优先指出 weak_words；如果 weak_phones 非空，再说明这些音素“可能”需要注意。
4. strong_words 可以作为正向反馈依据。
5. 如果证据不足，请明确说“建议结合音频复核”，不要编造。
6. 不要复述过多数字，除非个别分数对解释非常必要。
7. 输出分成四部分，并使用以下固定标题：
整体评价
读得较好的地方
需要改进的地方
练习建议

补充词典（可选）：
{dictionary_context}

评测记录：
{diagnosis_record_json}
```

## 极简 User Prompt 模板

如果你后面是在代码里批量调用模型，可以用这个更短的版本：

```text
请基于下面这条斐济语口语评测记录，生成面向学习者的中文反馈。

规则：
- sentence_only: 只做整体评价和正向反馈，不展开负面细分
- word_phone: 先说低分词，再说词内可能需要注意的音素
- weak_phones 只是证据，不要绝对化
- 证据不足时明确说明“建议结合音频复核”
- 输出标题固定为：整体评价 / 读得较好的地方 / 需要改进的地方 / 练习建议

词典补充：
{dictionary_context}

记录：
{diagnosis_record_json}
```

## 词典上下文建议

不建议把整本 `fijian_bootstrap_arpa.dict` 全量塞进提示词。

更好的做法是：

1. 先从当前记录中提取：
   - `reference_text`
   - `strong_words[].word`
   - `weak_words[].word`
2. 只查这些词在词典中的发音
3. 把查到的少量词条拼成 `dictionary_context`

例如：

```text
词典补充：
- bula -> B UW1 L AH0
- na -> N AA1
- yalewa -> Y AH0 L EH1 W AH0
```

这样既节省 token，也更聚焦。

## 推荐输出示例

下面是一种推荐风格：

```text
整体评价
这句话整体能听出目标内容，节奏和主要词形基本到位，但还有个别词需要再读得更稳定一些。

读得较好的地方
- “dua” 这一词整体比较稳定，和参考读音接近。
- 整句的基本节奏是对的，说明你已经掌握了大致的句子轮廓。

需要改进的地方
- “na” 这个词目前相对较弱，建议你单独多练几遍，把这个词读得更清楚、更完整。
- 在 “yalewa” 里，后半部分的发音稳定性略弱，尤其是对应的部分音素可能还不够清晰。这里更像是细节控制问题，不一定是整词都读错了。

练习建议
先把整句拆成 “e / dua / na / yalewa” 四段慢速练习，再把 “na” 和 “yalewa” 单独重复跟读。练的时候优先追求清晰和稳定，不要一开始就读得太快。
```

---

## 不建议的写法

以下做法应避免：

- 看到低分就直接说“你这个音读错了”
- 在 `weak_words` 为空时仍然硬写具体词或音素错误
- 把 phone 级证据当成绝对结论
- 只报分数，不给练习建议
- 仅凭词典中的音素串，硬解释复杂发音机制

## 下一步可扩展

如果你后面希望建议更专业，可以再补一层“音素知识库”，例如：

- `B`: 双唇浊塞音，带轻微鼻化特征
- `T`: 舌尖或齿龈部位阻塞后释放
- `NG`: 鼻音收尾，避免丢失尾音

那时可以把提示词再升级为：

1. 结构化诊断记录
2. 当前句涉及词的词典发音
3. 当前句涉及低分音素的教学知识

这样 LLM 给出的建议会更稳定，也更像真实教师反馈。
